# DD轨迹

> **把散落在直播间的每一次互动，连成一条属于你的轨迹。**

DD轨迹是一款面向 B 站个人用户的本地直播互动与消费分析工具。它记录本人弹幕、礼物、
醒目留言、上舰和进入直播间事件，并使用 danmakus 提供的公开历史数据补充本地缺失记录，
生成月、年、生涯三类可视化报告。

danmakus 官网：[https://danmakus.com/](https://danmakus.com/)

Windows 免安装版本：
[下载 DD轨迹 v1.2.0](https://github.com/laplace-dragon/DDTracker/releases/tag/v1.2.0)

## 项目简介

直播平台通常只展示余额、累计消费或零散通知，很难回答这些问题：

- 我真正参与最多的是哪些直播间？
- 每一笔礼物、SC 和上舰分别发生在什么时候？
- 过去一个月、一年或整个生涯的互动节奏有什么变化？
- 本地采集的数据与 danmakus 公开历史记录是否一致，有哪些遗漏？
- 进入直播间、发弹幕和付费行为之间的构成是什么样？

DD轨迹把这些信息整理成一套本地可运行的桌面客户端、互动记录页面和完整报告。

## 适合谁

- 想回顾自己 B 站直播观看与互动轨迹的用户；
- 想核对礼物、SC、上舰和消费记录的用户；
- 希望数据只保存在本机，不希望上传到第三方账号的人；
- 想按月份、年份或完整生涯查看互动趋势与频道偏好的用户。

## 核心功能

| 功能 | 说明 |
|---|---|
| 本地实时采集 | 只保留本人账号的公开直播事件 |
| 账号身份 | 扫码登录，显示真实头像、昵称和 UID |
| 互动记录 | 弹幕、礼物、SC、上舰、进入和手动补录筛选 |
| 月/年/生涯报告 | 可切换时间范围并重新统计 |
| 互动趋势 | 点击 X 轴筛选起始日期，可恢复完整范围 |
| 活跃日历 | 与生涯互动趋势双向联动；点击日期格也会切换趋势起点 |
| 频道偏好 | 互动、消费、弹幕和访问场次排行 |
| 打米记录 | 礼物、SC、上舰金额与逐笔明细；支持按类型和直播间筛选，每页 100 条分页 |
| 手动补录 | 通过客户端或本地 API 补录历史事件 |
| danmakus 数据同步 | 使用公开历史数据补充本地缺失项，只追加真正缺失的新事件 |
| 数据保护 | Cookie、采集数据和头像缓存默认不进入 Git 仓库 |

## 工作方式

1. 客户端通过 B 站扫码登录，只采集当前账号的公开互动事件；
2. 实时弹幕流和最近回补数据写入 `data/live_events.jsonl`；
3. 从 danmakus 获取公开历史数据，并由 DD轨迹独立完成去重、匹配和增量补缺；
4. 报告页面读取本地数据，生成月、年、生涯三类结果；
5. 所有默认数据路径都位于程序目录或用户指定的本地目录。

## 数据与隐私

- 只处理自己的 B 站账号；
- 只连接公开直播间，不绕过验证码或风控；
- 不逆向 B 站 App 私有接口；
- 登录凭证保存在本机 `cookie.txt`，不会由本项目上传；
- Git 仓库已配置严格忽略规则，不包含 Cookie、账号缓存、直播数据、报告或日志；
- 退出登录会停止采集，并清理登录凭证、身份和头像缓存，历史采集数据保留。

## 项目声明

DD轨迹是独立开源项目，不是 B 站官方产品，也不代表 danmakus 官方。

项目仅使用 danmakus 提供的公开历史数据作为补充来源。数据去重、实时与历史匹配、
增量同步、报告统计和可视化逻辑均由 DD轨迹独立实现，与 danmakus 的其他产品思路、
内部实现或数据处理方式无关。

# 使用说明

## 1. 启动客户端

双击：

```text
.\DD轨迹.exe
```

客户端同时负责：

- 桌面设置和系统托盘；
- 后台守护进程；
- 实时采集器；
- 互动记录网页；
- danmakus 数据同步；
- 报告生成。

关闭窗口默认隐藏到托盘，后台采集不会停止。

## 2. 首次登录

1. 点击账号卡中的动态登录按钮；未登录时显示“扫码登录”。
2. 使用 B 站手机 App 扫描二维码。
3. 在手机上确认登录。

登录成功后，客户端会显示：

- B 站真实圆形头像；
- 账号昵称；
- UID；
- 登录状态。

登录凭证只保存在本机 `cookie.txt`，不会上传到聊天窗口或第三方服务器。

如果 Cookie 过期，登录状态会恢复为未登录，需要重新扫码。

### 退出登录

扫码登录和退出登录共用一个动态按钮：

- 未登录时显示“扫码登录”；
- 已登录时显示“退出登录”；
- 扫码成功后自动切换为“退出登录”；
- 退出成功后自动切回“扫码登录”。

点击“退出登录”并确认后会：

- 停止当前采集；
- 删除本机 `cookie.txt`；
- 删除 `account_identity.json` 身份缓存；
- 删除账号头像缓存；
- 清空界面中的昵称、UID 和头像；
- 保留全部历史采集和报告数据。

退出后需要重新扫码登录，并点击“启动采集”恢复采集。

## 3. 主界面

### 身份卡

显示当前账号的头像、昵称、UID、登录状态和动态登录按钮。

### 实时状态卡

显示采集器是否在线、采集 PID、守护进程 PID 和心跳年龄。

- 绿色：采集在线；
- 黄色：手动暂停；
- 红色：采集离线。

### 控制矩阵

启动和停止采集已合并为一个动态按钮：

- 采集离线或暂停时显示“启动采集”；
- 采集运行时显示“停止采集”；
- 状态每 2.5 秒自动刷新。

其他按钮：

- 互动记录：启动本机互动记录服务，并打开带本次会话令牌的页面；
- 生成报告：生成月、年和生涯报告并自动打开；
- 刷新资产：更新 B 币、直播等级、亲密度和财富等级；
- 手动补录：补录弹幕、礼物、SC、上舰或进入事件。

客户端暂不显示“同步danmakus数据”按钮；后台同步代码、命令行入口和已有本地历史数据仍保留，见下文第 8 节。

### 运行日志

`SYSTEM FEED` 面板显示客户端操作结果。后台日志文件：

- `collector.log`：采集器；
- `watchdog.log`：守护进程；
- `console.log`：互动记录网页。

## 4. 报告

生成报告后会自动在浏览器中打开：

```text
.\live_report.html
```

报告支持：

- 月：选择任意月份；
- 年：选择任意年份；
- 生涯：全部本机数据。

生涯报告的互动趋势支持：

- 点击 X 轴选择起始日期；
- 只显示该日期及之后的数据；
- 重新计算柱形、折线、双纵轴和日期刻度；
- 右下角“恢复完整范围”返回全部生涯。

月报和年报保持完整范围趋势图。

报告账号名旁会显示真实头像。头像会优先使用本地 96×96 PNG 内嵌，离线也能显示。

进入直播间只计入“入场记录”，不会计入互动次数和互动趋势。

金额折算规则：

- 金瓜子礼物按 `total_coin / 1000` 元计算，银瓜子礼物免费；
- SC 的 `price` 本身就是元；
- 实时上舰优先读取同一笔 `USER_TOAST_MSG.price` 的实际成交单价；
- 没有本地结算事件时，用匹配到的 danmakus `Guard.priceMilli` 校正；
- 上舰金额统一按 `实付单价 × 开通月数 / 1000` 元计算；
- 手动补录的上舰保存的是总金额，按 `price / 1000` 元计算。

## 5. 互动记录

点击客户端的“互动记录”，或访问：

```text
http://127.0.0.1:8765/?token=<本次会话令牌>
```

页面包括：

- 今日行为；
- 消费统计；
- 我的直播行为；
- 我参与最多的直播间；
- 按类型筛选的历史明细，每页 100 条，可上一页、下一页或输入页码跳转；
- 数据来源对照；
- 直播间管理：开播房间优先，显示 B 站人气值，支持主播名/房间号搜索和每页 100 条分页；
- 采集模式：自动采集全部开播房间，或手动选择本次采集房间；
- 采集日志。

`GIFT_POPUP` 是 B 站账号级礼物广告/展示推送，不属于本人互动或消费记录。
采集端不再写入，读取旧数据时也会过滤，因此不会出现在记录列表或事件计数中。

直播间名称会依次从以下来源合并：

1. `rooms.json`；
2. `danmakus_history.json`；
3. `danmakus_v3_snapshot.json`。

因此直播间暂时被封禁、下播或从关注列表消失时，历史名称仍可正常显示，不会退化成裸房间号。

控制台右上角的启停、报告等操作已移除，运行控制统一由桌面客户端负责。

## 6. 设置

右上角“设置”统一管理：

- 采集数据目录；
- 刷新间隔；
- 开机自启；
- 关闭按钮行为；
- 最小化按钮行为；
- 事件分片归档阈值。

设置页支持纵向滚动。保存后，采集参数在下一次启动采集时生效。

采集模式开关位于互动记录页的“直播间管理”顶部：

- 自动采集全部开播：连接所有已关注且正在开播的直播间；
- 手动选择本次采集：只连接列表中勾选的直播间，可同时选择多个。

默认使用自动采集全部开播。

### 开机自启

开机启动项：

```text
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\DD轨迹自启.vbs
```

启动命令：

```powershell
DD轨迹.exe --autostart
```

旧版 `BiliLiveWatchdog.vbs` 会在新版客户端启动时自动迁移。

关闭开机自启会同时删除新旧启动脚本。

## 7. 数据保存位置

默认采集数据目录：

```text
.\data
```

| 文件 | 内容 |
|---|---|
| `data\live_events.jsonl` | 实时采集和手动补录 |
| `data\live_events.YYYYMMDD-HHMMSS.jsonl` | 达到归档阈值后保留的旧事件分片，不自动删除 |
| `data\danmakus_v3_remote_events.jsonl` | 全部远程历史事件本地基线 |
| `data\danmakus_v3_events.jsonl` | 本地缺失、需要补入的远程事件 |
| `data\danmakus_v3_guard_price_fixes.jsonl` | 匹配到的上舰实际成交价校正 |
| `data\danmakus_v3_snapshot.json` | 远程直播场原始快照 |
| `data\danmakus_v3_sync_state.json` | 增量同步边界 |
| `data\danmakus_v3_sync_audit.json` | 最近一次同步审计 |

程序根目录还保存：

- `settings.json`：客户端设置；
- `danmaku_sync_quota.json`：每日同步次数；
- `account_avatar_<UID>_96.png`：账号头像缓存；
- `console.token`：本次互动记录会话的临时访问令牌，服务退出后自动删除；
- `cookie.txt`：登录凭证，禁止外传。

在设置中切换数据目录时，程序会复制 `live_events*.jsonl` 和 `danmakus_v3_*` 到新目录，
旧文件保留。目标同名文件已存在时不会覆盖。

程序根目录的 `history_events*.jsonl`、`danmakus_history.json` 和
`live_account.json` 属于固定共享文件，不随“采集数据目录”移动。

## 8. danmakus 增量同步

客户端界面暂时隐藏同步入口。如需同步，请使用下方命令行：

默认流程：

1. 首次没有本地状态时建立全量远程基线；
2. 后续记录上次同步时间；
3. 历史列表按开播时间倒序获取，只请求到上次同步边界；
4. 上次仍在直播的场次会继续覆盖；
5. 只处理上次同步之后的新事件；
6. 全部远程事件保存在本地；
7. 与本地实时和补录数据匹配；
8. 只有真正新增的缺失事件才进入补充集。

历史接口没有 `startTime` 参数，因此服务器不能直接按日期查询。客户端利用倒序分页提前停止，
不会每次重新获取全部历史页。

命令行：

```powershell
DD轨迹.exe sync-danmakus
DD轨迹.exe sync-danmakus --cached
DD轨迹.exe sync-danmakus --full
```

- 默认：增量同步；
- `--cached`：不联网，使用已有快照；
- `--full`：强制重建全量远程基线。

### 每日次数

每个香港自然日最多同步 5 次：

- 第 1～5 次正常执行；
- 第 6 次起提示“已到当日使用上限”；
- 计数写入 `danmaku_sync_quota.json`；
- 网络是否成功都占用一次；
- 不能通过多开或连续点击绕过。

审计字段：

- `new_remote_events`：本次远程基线中的新事件；
- `matched`：新事件与本地匹配数；
- `remote_only_added`：本次真正新增到补充集的条数；
- `supplement_total`：当前补充集总条数。

## 9. 手动补录

客户端“手动补录”支持：

- 弹幕；
- 礼物；
- 醒目留言；
- 上舰；
- 进入直播间。

金额单位统一为元。可以标记时间或金额为估算。

保存前会检查同房间、同类型、同内容和同金额的近似记录。上舰总金额相同但数量不同时也会提示，
因为多月上舰容易在补录时误用默认数量 `1`。疑似重复不会自动写入，必须明确确认后才能继续。

本地接口：

- `GET /api/manual`：查看格式；
- `POST /api/manual`：提交补录。

互动记录页面的所有 `/api/*` 请求都要求本次会话令牌。通过客户端打开的页面会自动携带；
手工调用接口时，需要读取 `console.token` 并添加请求头 `X-DD-Token`。无令牌请求返回 HTTP 403。
疑似重复时 API 返回 HTTP 409 和候选记录；确认仍要保存时传 `"confirm_duplicate": true`。

详细示例见 `API.md`。

## 10. 进程与心跳

正常运行时只有一套逻辑实例：

- 1 个客户端；
- 1 个采集器；
- 1 个守护进程；
- 1 个互动记录服务。

任务管理器中可能出现同名的父/子进程，这是 PyInstaller 单文件程序的正常结构，不是重复实例。

三个心跳分别表示：

- `collector.alive`：采集器；
- `watchdog.alive`：守护进程；
- `console.ready`：互动记录网页。

心跳只证明进程存活。采集器内部还会检查是否持续收到服务器帧。

## 11. 常见问题

### 采集显示离线

检查：

1. `collector.log` 最后 30 行；
2. `collector.alive` 是否持续更新；
3. 客户端是否显示守护进程在线；
4. 是否手动存在 `collector.disabled`。

点击动态按钮“启动采集”可以恢复。

### 直播间显示成数字房间号

程序会从房间清单、旧 danmakus 历史和 v3 快照中查找名称。已修复“直播间暂时封禁后名称丢失”
的问题。

### Cookie 失效

重新点击“扫码登录”。不要将 `cookie.txt` 内容发送给他人或在线工具。

### 报告没有自动打开

手动打开：

```text
.\live_report.html
```

并检查 `console.log` 或生成报告时的 `SYSTEM FEED` 日志。
